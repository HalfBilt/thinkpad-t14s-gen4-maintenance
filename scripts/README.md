# scripts/ 脚本总索引

> 本目录 = **一次性 / 按需执行的工具脚本**。常驻服务（`CpuPLFixSvc` / `T14sFanSvc` / HUD）的代码不在这里，
> 在 <https://github.com/HalfBilt/T14scontrol>，部署到 `%APPDATA%\T14scontrol`。
>
> 跑之前先看 [`../03-EC-寄存器与读写.md`](../03-EC-寄存器与读写.md) 的「并发规则」——
> **任何自己写的 EC 脚本都必须串行、复用同一把锁**，两个进程同时裸跑会互相插队读到别人的应答。

## 一、按用途分

### 1. 体检 / 诊断（只读，最常用）

| 脚本 | 干什么 | 权限 | 输出 |
|---|---|---|---|
| `体检.bat` → `health-check.ps1` | **一键体检**：系统/应用错误 · 设备异常 · 驱动包 · 关键服务 · 安全 · 音频(WinSoftVol/SAC/Code39) · 降频值守 · 固件限速(EID37) | 普通（个别项标注需提权） | 屏幕 + `体检报告-时间戳.txt` |
| `10-性能自检.bat` / `.py` | **判断有没有被降频**：功耗墙读数 · 当前倍频 · 单线程睿频 · 满载功耗，末尾给判读 | 管理员（自动提权） | 屏幕 + `性能自检-时间戳.txt` |
| `13-EC诊断.bat` / `.py` | **EC 全面体检**，子命令见下 | 管理员 | 屏幕 + `EC体检-时间戳.txt` 等 |
| `14-EC总线实测.bat` / `.py` | 判定"EC 串位率"是**真总线错误**还是统计口径虚高（把读失败/哨兵不符/值变动拆开算） | 管理员 | 屏幕 + `EC总线实测-时间戳.txt` |
| `fan_ab_test.py` | **风扇控制 A/B**：同样 4 进程负载下比「原生 `0x80`」与「本工具曲线」。`fan_ab_test.py ours`（普通权限，只读 status）· `fan_ab_test.py native`（管理员，会停服务并写 `0x80`） | ours=普通 / native=管理员 | 屏幕 + `风扇AB-<mode>-时间戳.txt` |
| `31-事实核对.ps1` | **把手册里"可复核的断言"一次跑完**：机型/BIOS/内存/安全启动/VBS/bcdedit/电池/服务/计划任务/status 快照/EC 只读/事件统计。设计成逐项写盘、单项失败不中断；**非提权时 EC 段自动跳过**（`ensure_driver` 会尝试提权并卡住） | 管理员（非提权也能跑，少 EC 段） | `事实核对-时间戳.txt` |
| `15-EC延时对照.bat` / `.py` | **受控对照**：写完偏移后等多久才读，对读错率的影响（证明"越等越容易撞车"） | 管理员 | 屏幕 + `EC延时对照-时间戳.txt` |

`13-EC诊断.py` 的子命令：

| 子命令 | 用途 |
|---|---|
| `dump` | 全寄存器扫描 `0x00~0xFF`，逐个读 + 按 DSDT 命名解码（约 15 秒） |
| `temp` | 只看 8 个温度传感器（`TMP0`/`GPUT`/`TTS1~4`/`ATMX`/`HWAT`），采样 10 次 |
| `fan` | 风扇档位 `0x2F` + 转速 `0x84/0x85`，并验证"不写 `0x31` 能不能读到转速" |
| `batt` | 电池充电阈值 `BSC0/BEC0/BSC1/BEC1` + ACPI 判据 + 系统电量 |
| `batt set S E` | 设充电阈值（低于 S% 才充、充到 E% 停）—— **优先用联想软件改**，这里是备用手段 |
| `throttle [秒]` | 抓锁频瞬间：PL + PROCHOT + EC 标志 |
| `watch [秒]` | 现场标定未知位（配合 `05` §5 的未解项） |
| `smi` | **只读** SMI 邮箱（`05` §3） |

### 2. 散热 / 风扇实测（会碰硬件，看情况跑）

| 脚本 | 干什么 | 注意 |
|---|---|---|
| `11-满载温度60秒.bat` / `.py` | 全核满载 60 秒的温度 / 功耗曲线（可传秒数） | 用来定 PL1 该给多大，见 [`../01`](../01-CpuPLFix-降频修复.md) §3.3。**温度用 DTS 推算，只看趋势** |
| `12-风扇天花板实测.bat` / `.py` | 测 **EC 自动档**（`0x80`）到底能给多少转速 | **会临时停 `T14sFanSvc`**；跑完自动恢复 |
| `16-风扇档位扩展探测.bat` / `.py` | 验证 `0x2F` 在 `0x08~0x3F` 是否还有真实档位（无负载逐点试） | 要求 EC ≤75°C 才开测；收尾写回 `0x80` 并启动风扇服务 |
| `17-风扇8档28W实测.bat` / `.py` | `0x08` 到底是不是**独立中间档**：同温度、充分沉降的 7/8 档 A/B，必要时再加 28W 满载 | 结论已进 [`../02`](../02-风扇与过热保护.md) §1.1：`0x08~0x3F` 与 `0x07` 同速，**没有可用中间档** |

> 这三个风扇脚本都**依赖已装的 CpuPLFix**（借 `TSCtl` 驱动 + 加固读法），并且都会在收尾把 `0x2F` 写回 `0x80`。
> 中途强杀进程会让风扇停在某个固定档 —— 手动 `sc start T14sFanSvc` 即可恢复。

## 二、通用规矩

| 规矩 | 说明 |
|---|---|
| **报告不入库** | 所有 `*-时间戳.txt` 已被 `.gitignore` 排除。它们是**当时的实测记录**，换机器/改配置后不代表现状 |
| **编码** | `.ps1` = UTF-8 **with BOM**（PS 5.1 无 BOM 会按 ANSI 读，中文注释直接语法报错）；`.bat` = UTF-8 **无 BOM** + `chcp 65001`；`.py` = UTF-8 无 BOM。详见 [`../07`](../07-工具部署与目录结构.md) §4 |
| **管理员** | 凡是要开 `\\.\TSCtl` 的（`10`~`17`）都必须管理员。双击 `.bat` 会自动弹 UAC；**非管理员硬跑会卡住，只能杀进程** |
| **改脚本后** | `.py` 改完至少跑一次 `python -c "import py_compile"` 之类；`.bat` 改完必须**实跑一次**（bat 对 `if ... )` 与命令挤同行这类解析极敏感，双击无效很常见） |
| **EC 操作** | 任何新写的脚本读写 EC 都要复用 [`../03`](../03-EC-寄存器与读写.md) §3 的锁与保险：逐事务拿锁、连读两次一致、25 ms 节流、写后回读校验 |
